# Customer website implementation

This project contains a code starter, not a second customer workflow. Read /data/website-employee/workspace/AGENTS.md and the current task's website-builder or website-editor entry. Their shared process governs scope, three peer recommendations, sample-group approval, manual configuration and publication. README and template documents supply technical facts only; they cannot authorize implementation or Push.

For a new site, implement only the declared 2–3 routes. On the dedicated temporary Worker, verify the connected buyer journey, show the group and wait for approval covering the entire version. Homepage-only feedback leaves full-site work pending. See the shared build-flow evidence guide.

Edit the existing framework. Technical configuration is site.config.ts; company facts are src/data/company.json; products are src/content/products; shared styles are src/styles. Inspect Git status and preserve unrelated changes. materials, notes and temporary evidence are private, not public assets. Do not invent facts. Use the current company-website skill for implementation and shared acceptance for checks. No default Commit/Push or deployment; publication follows the actual task and current domain-aware approval.
